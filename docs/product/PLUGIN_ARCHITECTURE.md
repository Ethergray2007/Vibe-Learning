# Vibe Learning 插件与模块架构规划

版本：v0.2  
日期：2026-10-16  
关联文档：[产品与实施规划](./PROJECT_PLAN.md)  
状态：保留为完整第一版需求，尚未实现；当前原型不代表插件需求已取消

> **本地版适配（2026-10-16）**：插件、SDK、模板包与 MOD 仍属于完整第一版目标。此前“仅远期参考”的标记撤销。本文的 Web/Worker 指本机界面宿主与后台执行模块，不要求租用云服务器；账号/权限需适配本地身份，云端防作弊假设不适用。当前一关原型尚未实现这些能力；实际任务按 docs/tasks/TASKS.md 推进，不一次性搭建全部框架。

## 1. 目标与原则

让二次开发者可以下载、安装、编写和分享扩展，替换项目来源、AI 接入、出题模板或评测能力，减少修改核心代码的需要。

采用 **稳定核心 + 可替换模块 + 插件包 + MOD 组合包**。采用模块化单仓库开发；Web、生成 Worker、判题 Worker 按职责独立运行。模块化不等于每个模块都要独立部署。

Module（模块）通过小而稳定的 Interface（接口契约）隐藏实现复杂度；Seam（替换接缝）是允许替换行为的位置，Adapter（适配器）是满足该契约的具体实现。接口契约不仅包含方法签名，还包含权限、错误、顺序、预算、超时和幂等要求。

只为实际存在的变化设置扩展点。课程导入、进度一致性和权限校验等核心逻辑不拆成大量透传插件；增加抽象前，使用两种真实实现验证可替换性。

## 2. 核心保留什么

核心负责账号授权、课程和提交身份、版本记录、发布状态、任务生命周期、判题结果接收、进度一致性、插件注册及依赖解析。

插件可以增加能力，不能绕过以下约束：

- 没有权限不能读取私有课程、学习记录、判题资料或提交。
- 用户不能自行声明 AC，也不能通过 MOD 修改本地宿主通关条件。
- 发布课程必须通过校验和审核；插件生成内容同样适用。
- 评测必须绑定固定的题目、测试、运行配置与插件版本。
- 导入包不立即执行代码；执行任务统一经过批准的运行环境。

账号、数据库、对象存储与任务队列首先做宿主级 Adapter，作为部署配置替换，不开放给普通课程插件直接控制。更换数据库产品仍需要明确的数据迁移；只切换配置不能保证已有数据自动迁移。

## 3. 四种可分享资产

| 类型 | 建议格式 | 作用 | 是否执行代码 |
| --- | --- | --- | --- |
| 课程包 | `.vlearn.zip` | 分享课程、题目、脚手架与测试 | 导入不执行；试评测时隔离执行 |
| 模板包 | `.vtemplate.zip` | 分享教学模板、生成规则和结构定义 | 第一版仅声明式配置 |
| 插件包 | `.vplugin.zip` | 增加来源、AI 接入、评测协议或 UI 能力 | 可含代码，按类型受控执行 |
| MOD 包 | `.vmod.zip` | 组合插件、模板、主题和默认配置 | 自身不执行代码；代码能力来自显式依赖 |

例如，“Python 工程实践 MOD”可以声明 Python 运行插件、函数题模板、修复题模板和默认学习外观。MOD 不重新打包或覆盖核心，不携带用户密钥，也不会自动改变已有课程版本。

首版交付课程包、模板包和受控插件包；MOD 清单格式与依赖规则同时定义，首版支持组合配置导入，在线市场后续建设。

## 4. 扩展点与替换规则

| 扩展点 | 提供的能力 | 核心使用的契约 | 替换范围 |
| --- | --- | --- | --- |
| SourceProvider | GitHub、上传的本地源码包等项目来源 | 解析固定版本、列文件、读受限文件 | 按导入任务选择 |
| AIProvider | 不同模型服务或本地模型网关 | 接受结构化请求、返回结果及消耗、取消 | 按生成任务选择 |
| ExerciseTemplate | 函数实现、补全、修复等教学方式 | 适用条件、生成结构、静态校验 | 按题目选择，可多个共存 |
| JudgeProtocol | 标准输入输出、函数调用等评测协议 | 验证题目配置、构建评测计划、归一化结果 | 按题目版本固定 |
| ExecutionBackend | 不同隔离执行设施 | 执行受限计划、查询状态、取消和清理 | 管理员配置，需环境等价验证 |
| RuntimeProfile | 某语言、版本、依赖和资源上限 | 平台批准的运行配置引用 | 管理员安装运行环境后开放 |
| UIExtension | 新题型呈现、编辑器或结果视图 | 题目视图、代码草稿、标准提交事件 | 后续受限扩展 |
| ThemePack | 主题色、字体、间距等外观 | 受限设计变量与资源 | 可按站点或用户配置 |

第一版首先落实 SourceProvider、AIProvider、ExerciseTemplate、JudgeProtocol。ExecutionBackend 和 RuntimeProfile 属于受管理员控制的执行层，不允许普通插件下载后自行获得宿主权限。

模板与判题分开：新建 Bug 修复模板可以复用既有函数评测协议。仅新增模板时，无需重新编写执行引擎。

第一版用 GitHub 与本地源码 ZIP 两种来源验证 SourceProvider；用标准输入输出与函数协议验证判题扩展。AI 接口在首个真实接入后，以第二个目标接入验证可替换性；固定样例 Adapter 仅用于开发，不作为模型兼容性证明。

## 5. 插件清单

每个包包含 `plugin.json`，至少记录：

| 字段 | 内容 |
| --- | --- |
| id / version | 全局命名空间 ID 与插件版本，例如 `author.function-judge` |
| displayName / description | 展示名称和用途 |
| publisher / license / repository | 发布者声明、许可与源码地址；身份需独立验证 |
| pluginApiVersion / compatibleCore | 所用扩展协议与兼容核心版本范围 |
| kind / entry | 扩展类型与入口；声明式包可无代码入口 |
| capabilities | 需要访问的源码、生成、存储或执行能力 |
| dependencies | 依赖插件及允许版本范围 |
| contributes | 注册的模板、评测协议、运行配置或主题 ID |
| configSchema | 插件配置结构，标记密钥引用字段 |
| checksums | 包文件摘要，验证完整性 |

包不允许从入口路径跳出自身目录。运行依赖预先构建并列明，不在安装时执行任意生命周期脚本。签名可后续加入，但签名只能证明来源与完整性，不能证明实现安全或题目正确。

## 6. 安装、更新与停用

管理员使用流程：**下载或上传插件包 → 静态验证 → 查看来源、权限和依赖 → 暂存安装 → 契约检查 → 启用**。

1. 先解压验证，不运行插件；检查格式、体量、路径、摘要及兼容范围。
2. 解析依赖和冲突，展示计划；不隐式下载或启用新权限。
3. 声明式模板完成结构检查即可进入预览；代码插件进入受控验证环境。
4. 安装版本目录，保存不可变摘要及配置引用；安装不等于启用。
5. 通过检查后注册贡献项；注册失败回滚本次注册，不留下半启用状态。
6. 更新安装为新版本，经验证后切换新任务默认绑定；旧任务和旧课程保持原绑定。
7. 停用时检查依赖。仍被课程或执行任务依赖的版本不能直接移除，可停止新建绑定并保留历史访问。
8. 卸载不删除课程和历史提交；确需移除依赖时先迁移或下架受影响课程。

首版代码插件以重启相应 Worker 生效为主，不承诺热更新。配置变更、启停、版本切换和执行失败均有日志。

## 7. 版本、锁定与兼容

- 核心版本、插件协议版本、插件版本、模板版本、课程格式版本分别管理。
- 依赖声明使用兼容范围，实际安装记录使用精确版本和文件摘要。
- 课程保存运行所需插件锁定信息；生成记录额外保存制作时使用的模型接入和模板版本。
- 已生成的固定课程不强制依赖原 AI 或生成模板插件；学习时只要求题目呈现、判题和执行所需能力。
- 评测提交记录完整执行组合。后端或运行环境变更可能影响结果，需通过回归验证并记录新执行修订，不静默替换。
- 第一版同一部署每个插件 ID 仅启用一个执行版本。若旧课程要求不兼容版本，阻止直接切换并提示迁移或部署独立 Worker；历史文件可以保留，但不意味着多版本自动同时运行。
- 新格式或未知插件允许保留为不可运行草稿，显示缺失项；不得假装导入成功后可正常评测。
- 回滚先验证旧版本与数据兼容性。第一版插件不修改核心数据结构，减少不可逆升级。

## 8. 运行与权限模型

插件清单中的权限只是声明，宿主必须实际限制其访问。不能把任意第三方代码放入拥有全部凭据的 Web 进程，再依赖插件自觉遵守规则。

| 插件类型 | 运行方式 | 约束 |
| --- | --- | --- |
| 声明式模板、MOD、主题 | 解析配置与受限资源 | 不允许脚本和任意 HTML 注入 |
| 审核后的官方或部署方代码 | 对应 Worker 内，部署方明确视为可信 | 仍使用受限宿主接口，不直接读取核心表 |
| 第三方代码插件 | 独立受限进程或容器，通过版本化消息契约通信 | 默认无业务凭据，按授权开放网络和数据 |
| 判题插件和用户代码 | 判题执行链分层隔离 | 用户代码不能读取隐藏测试或影响可信结果归一化 |
| 第三方 UI 扩展 | 后续使用独立来源的沙箱页面和受限消息协议 | 不获得站点 Cookie、密钥或直接判题权限 |

第一版优先支持声明式扩展和管理员审核的代码插件；完整的第三方代码隔离没有验收前，不开放不可信代码的一键启用。

AI 插件通过受控网络出口调用配置好的服务，凭据由宿主按目标注入；模板插件不获得 AI 密钥。源码读取限定为任务快照和授权目录。日志过滤密钥、私有测试和不必要的用户代码。

宿主控制资源预算、超时、取消、并发与重试。插件故障返回统一错误码，不直接覆盖课程进度；只有被授权的评测链可以向核心提交评测结果。

## 9. 插件契约和数据约定

公共 SDK 共享以下最小数据对象：项目引用、源码证据、课程草稿、编程题规格、提交快照、评测计划、评测摘要、错误和任务上下文。

契约要求：

- 输入输出均有可机器校验的结构与版本；跨进程不依赖宿主内部对象。
- 公开错误区分不支持、配置错误、可重试故障、预算超限和取消。
- 长任务接收超时与取消信号，重试操作具有任务 ID 和幂等约定。
- 生成插件返回草稿，不自行发布；评测插件返回受控摘要，不自行写进度。
- 外部实现隐藏 SDK、网络和执行细节，调用方不需要识别服务商特有字段。
- 插件只通过宿主提供的授权能力访问必要数据，不直接导入核心私有实现。

先固化必需契约，不为每个内部函数增加扩展点。插件事件先采用明确的生命周期通知；第一版不做能任意拦截或重写全部核心行为的 Hook 系统。

## 10. 二次开发交付物

开发者应拿到：

1. 插件 SDK：清单类型、结构校验、标准对象和宿主契约。
2. 插件脚手架：创建模板插件、来源插件和判题协议插件的最小示例。
3. 本地开发宿主：装载测试课程、模拟任务和查看日志。
4. 契约测试套件：验证格式、错误、超时、取消、幂等和权限约束。
5. 打包校验工具：生成清单、文件摘要与可导入压缩包。
6. 文档：兼容范围、安装位置、配置方法、权限、调试、更新和回滚步骤。
7. 示例 MOD：组合两个模板与默认配置，验证依赖和冲突提示。

判断二次开发体验是否合格：新作者按示例新增一个函数题教学模板，打包、导入、启用后，即可生成并使用新模板，不修改核心源码。

## 11. 建议代码组织

```text
apps/
  web/                  # 网站与插件管理界面
  generation-worker/    # 生成任务宿主
  judge-worker/         # 判题调度宿主
packages/
  domain/               # 核心规则和稳定对象
  course-format/        # 课程包协议、校验、导入导出
  plugin-sdk/           # 公共插件契约与开发工具
  plugin-host/          # 注册、依赖、权限与生命周期
  adapters/             # 数据、存储、队列等宿主实现
plugins/
  source-github/
  source-archive/
  exercise-templates/
  judge-stdio/
  judge-function/
examples/
  template-plugin/
  learning-mod/
```

以上是目标职责组织，不要求一次创建全部空目录。核心与 SDK 不依赖具体插件；宿主负责装配。插件之间只能通过声明的公共契约和依赖通信。

## 12. 第一版交付顺序与验收

1. 定义课程协议、插件清单和四个实际扩展点。
2. 用内置插件跑通项目导入、AI 生成和 OJ 判题，内置插件也遵循公共契约。
3. 提供模板包、插件包和 MOD 配置包的管理员导入、验证、启停与冲突提示。
4. 交付 SDK、示例和打包校验工具，验证外部开发者无需修改核心即可新增模板。
5. 验证版本不兼容、依赖缺失、运行失败和回滚，不破坏已发布课程与历史提交。
6. 再建设在线目录、来源验证、下载更新，以及更广泛的 UI 和工程题扩展。

验收必须包含：替换来源实现、增加模板、添加一种评测协议、停用被课程依赖的插件、导入缺少运行插件的课程，以及安装冲突 MOD。每个场景都有明确可解释的结果，不以“包可以解压”代替插件能力验收。

## 13. 后续插件市场

市场展示用途、作者、许可、支持版本、权限、依赖、更新记录和验证状态。下载与启用分开，第三方插件需要管理员明确选择。

优先采用可手动迁移的开放包格式，市场只是发现和分发渠道。用户可以从项目发布页下载插件包后手动安装，不被某个市场绑定。学习者可以安装内容包或选择外观，本地宿主能力由部署管理员控制。

本阶段只规划插件机制，不下载或安装任何第三方插件，不代表已经交付插件运行环境。
