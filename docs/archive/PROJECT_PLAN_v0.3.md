# Vibe Learning 产品与实施规划

版本：v0.3  
日期：2026-10-16  
状态：规划草案，可作为第一版开发依据

## 1. 产品定位

Vibe Learning 是一个围绕 GitHub 真实项目组织学习路线的编程闯关平台。核心体验借鉴 OJ：阅读题目、实际敲代码、运行样例、提交评测、根据结果修改，AC 后解锁下一关。作者通过 AI 分析项目，使用可复用模板生成题目、初始代码、参考实现和测试，审核后形成可导入、导出的课程包。

编程题是课程主线，单选、多选和排序题作为理解检查的辅助。平台既支持标准输入输出题，也支持更贴近真实项目的函数实现、代码补全、Bug 修复和受限多文件功能题。产品不以算法竞赛训练为唯一目标，而是让学习者通过写代码掌握项目中的能力。

核心目标：**一次制作课程，多人重复学习；课程可以迁移，进度相互独立。**

架构目标：**稳定核心 + 可替换模块 + 可下载安装的插件与 MOD**。课程、模板、模型接入、项目来源、评测协议和外观分别扩展，二次开发优先编写插件，不修改核心。详细约定见 [插件与模块架构规划](./PLUGIN_ARCHITECTURE.md)。

产品由两个部分构成：

- **课程制作工具**：项目导入、源码分析、路线规划、模板出题、校验、编辑、发布与导出。
- **闯关学习平台**：课程展示、在线代码编辑、样例运行、提交评测、判题反馈、关卡解锁与进度记录。

第一版的使用假设：由平台作者制作公开仓库的课程，支持多个学习者使用；第三方作者入驻和课程市场暂缓。

## 2. 用户与使用场景

| 用户 | 主要需求 | 产品提供的结果 |
| --- | --- | --- |
| 课程作者 | 把一个项目变成有教学顺序的课程 | 可编辑、可校验、可分发的课程包 |
| 有基础的学习者 | 不知道从哪里开始阅读真实项目 | 具体到文件和功能的学习路线 |
| AI 编程学习者 | 能生成代码，但难以理解和修改代码 | 阅读、预测、排错与修改练习 |
| 平台管理员 | 控制课程质量并维护内容版本 | 草稿审核、版本记录与发布管理 |

每门课明确前置知识。第一版不承诺任意复杂仓库都能自动转化为适合零基础的课程。

## 3. 核心产品流程

1. 作者输入 GitHub 仓库地址，选择版本和学习范围。
2. 系统获取并固定源码快照，生成文件清单。
3. AI 分步分析项目，输出带源码依据的项目报告。
4. 作者确认目标人群、学习目标与课程路线。
5. 系统按模板生成题面、接口契约、初始代码、参考实现、公开样例、隐藏测试、提示和解析。
6. 自动校验结构、引用、关卡依赖，并在隔离环境验证参考实现和测试质量。
7. 作者预览学习体验，修改并审核课程。
8. 发布课程，或导出完整课程包用于备份和迁移。
9. 学习者编写代码、运行公开样例、提交评测；服务端返回判题结果，保存进度并解锁后续关卡。

AI 主要在制作阶段使用。代码题依靠可复现的执行结果和测试判题，客观题使用确定性规则；第一版的学习和判题不依赖实时 AI 调用。

## 4. 第一版范围

### 4.1 必须完成

- 公开 GitHub 仓库导入，绑定固定 commit，可限定目录或功能范围。
- 分步骤的 AI 项目分析与课程草稿生成。
- 编程题主线：标准输入输出题、函数实现题、代码补全题、Bug 修复题。后面三类共用函数或模块测试引擎，避免为每种教学模板重复建设判题系统。
- 初期仅支持一种运行语言，以首个项目决定；暂定 TypeScript/JavaScript 运行配置，开发前确认。题型和协议预留多语言能力。
- 浏览器代码编辑、代码草稿保存、公开样例运行、正式提交、评测状态和提交历史。
- 隔离判题服务、任务队列、公开样例与隐藏测试、资源限制和超时终止。
- 每道编程题具有题面、学习目标、源码依据、接口或输入输出契约、初始代码、参考实现、测试和解析。
- 单选、多选、排序作为辅助，不能替代必做编程题。
- 课程、章节、关卡、题目的组织与基础编辑。
- 草稿校验、预览、审核和发布。
- 版本化课程包的导入、完整导出与基础兼容检查。
- 登录、服务端判题、线性解锁、继续学习和独立进度。
- 生成任务状态、失败原因、重试及单关重新生成。
- 插件协议、插件清单和本地包导入，支持安装、启用、停用、兼容检查及版本锁定。
- 第一批真实扩展点：内容来源、题型模板、AI 接入和评测协议；以共用协议验证不同实现可以替换。
- 开发者 SDK、最小插件示例和契约测试。第一版支持管理员安装审核后的插件，不向普通学习者开放服务端代码安装。

### 4.2 暂不包含

- 任意语言和任意规模仓库的完整自动教学支持。
- 私有仓库授权、包含终端和自由安装依赖的完整在线 IDE。
- 用户自由配置运行镜像、网络访问及任意系统命令。
- 第一版以可独立测试的函数和模块为范围；浏览器 UI 自动评测、真实外部服务集成、多容器项目后续支持。
- AI 开放问答判分、实时 AI 助教。
- 支付、作者分成、公开课程市场、社交排行榜。
- 自动跟随仓库最新版本更新已发布课程。
- 向量数据库、多 Agent 编排和复杂的个性化推荐。
- 自动在线插件市场、任意第三方前端脚本注入、运行中热替换核心、任意 MOD 改写权限或判题结果。

### 4.3 最小验收场景

选择一个体量小、核心逻辑可以独立测试的开源项目，制作约 6～8 关课程，每关至少有一道必做编程题。用户能够在线敲代码、运行公开样例、正式提交隐藏测试，并在 AC 后解锁下一关。课程经过生成、审核、导出和重新导入后，代码模板、测试与判题配置仍能使用。两个账号的代码草稿、提交和进度互不影响，学习与评测无需调用 AI。

## 5. AI 项目分析与出题流程

### 5.1 源码准备

- 将仓库地址解析为明确的 owner、repo 和 commit。
- 记录文件路径、内容摘要和内容哈希，保存必要的源码快照。
- 排除依赖目录、构建产物、二进制文件和不适合教学的超大文件。
- 设置仓库体量、读取文件数、单文件长度和生成预算上限。
- 不把环境文件、密钥或凭据作为课程材料；导入分析时不自动运行原仓库的安装、构建或启动脚本。课程制作阶段只在隔离评测环境执行经过审核的题目工程与测试。
- 将仓库文字和源码注释作为待分析材料，不作为修改生成规则或执行操作的指令。

### 5.2 分步产出

| 阶段 | 输入 | 输出 | 校验重点 |
| --- | --- | --- | --- |
| 项目扫描 | 文件树、说明文件、依赖声明 | 目录结构、技术栈、运行说明、候选入口 | 区分源码事实与推断 |
| 功能分析 | 入口及相关实现文件 | 模块、核心功能、调用链、数据流 | 结论关联具体代码 |
| 教学规划 | 项目分析、目标人群、学习范围 | 前置知识、学习目标、章节和关卡 | 难度递进、内容不重复 |
| 模板出题 | 关卡目标、证据片段、题型模板 | 题面、契约、初始代码、参考实现、样例、隐藏测试、解析 | 任务可独立完成，判分可执行 |
| 自动校验 | 课程草稿、源码快照、题目工程 | 静态检查与隔离试评测报告 | 引用、结构、依赖、参考实现与测试有效性 |
| 作者审核 | 校验后的课程 | 可发布版本 | 教学准确性与可理解性 |

分析结果与生成中间结果均保存。单题或单关失败时，重试对应步骤，不重新分析整个仓库。

### 5.3 质量要求

- 源码事实附带文件路径、commit、代码片段和定位信息；不能只依赖易变化的行号。
- 涉及执行结果时明确输入、环境和前置条件，避开未控制的随机性、时间和外部服务。
- 错误选项对应合理误解，解析说明原因。
- AI 自检只作为辅助，不能替代程序校验和作者审核。
- 无法确认的结论标记待审核，不自动发布。
- 重新生成草稿时保留已有人工编辑版本，避免静默覆盖。
- 先确定行为契约和测试，再验证参考实现；避免参考答案与测试共享同一个错误假设。源码当前行为与教学要求不同时，题面必须明确差异。
- 参考实现必须通过全部测试；初始代码或预设错误版本必须无法通过关键测试，教学脚手架不能直接 AC。
- 测试包含正常、边界、异常输入，以及针对常见错误实现的检查。通过人为植入错误版本验证测试能否拦截问题，不只检查覆盖率。
- 支持符合契约的不同实现，不要求与参考实现逐字相同；不使用字符串匹配源码作为主要判题方法。
- Bug 修复题包含能复现问题的测试和防止破坏已有功能的回归测试。

## 6. 可复用模板设计

模板由题型规则、生成指令、数据结构和校验规则组成，按版本管理。模板决定如何出题，具体课程保存生成后的固定内容。

| 模板字段 | 含义 |
| --- | --- |
| templateId / templateVersion | 模板身份和版本 |
| questionType / judgeMode | 教学题型与执行协议分别记录，例如 Bug 修复 + 模块测试 |
| learningObjective | 需要验证的能力 |
| applicability | 适合哪些代码结构和学习阶段 |
| requiredEvidence | 生成题目必须具备的源码依据 |
| generationInstructions | 生成要求、限制和示例 |
| outputSchema | 题面、接口、初始代码、样例、测试、参考实现和解析的结构 |
| validationRules | 可程序化检查的约束 |
| gradingPolicy | 通过规则、输出比较方式与可见反馈范围 |
| runtimeProfile | 允许的语言、版本、依赖和预置评测配置 |
| resourceLimits | CPU、内存、运行时限、输出和文件大小限制 |
| editableFiles | 学习者允许修改的文件及提交约束 |

教学模板规划：

| 模板 | 学习者实际任务 | 执行协议 | 优先级 |
| --- | --- | --- | --- |
| 标准输入输出 | 从项目抽取解析、计算或转换逻辑，编写完整程序 | stdin/stdout | 第一版 |
| 函数实现 | 根据签名和行为契约实现一个函数 | 函数或模块测试 | 第一版 |
| 代码补全 | 在给定脚手架中完成缺失逻辑 | 函数或模块测试 | 第一版 |
| Bug 修复 | 修改错误实现，使复现和回归测试通过 | 函数或模块测试 | 第一版 |
| 功能扩展 | 修改多个允许编辑的文件，增加一个功能 | 多文件工程测试 | 后续扩展 |
| 重构 | 保持行为兼容，完成明确结构约束 | 回归测试 + 可验证结构规则 | 后续扩展 |
| 性能优化 | 在正确性不变的前提下满足资源要求 | 正确性 + 稳定的性能评测 | 后续扩展 |
| 测试编写 | 编写能识别预设错误实现的测试 | 对正确实现与错误变体分别执行 | 后续扩展 |
| SQL 查询 | 基于固定数据集完成查询 | 数据库结果比较 | 后续扩展 |
| 代码定位、行为判断、流程排序 | 辅助理解与自测 | 客观题规则 | 第一版辅助 |

题型数量与评测引擎数量分开：第一版用 stdin/stdout、函数或模块测试两种执行协议覆盖四类编程任务。模板不适合当前代码时跳过，不以凑题数量为目标。

### 6.1 编程题最小规格

每题必须定义题面、输入输出或函数签名、输入范围、边界规则、示例与解释、初始工程、可编辑文件、运行配置、资源限制、公开测试、隐藏测试、参考实现和通关规则。

- 标准输出比较明确选择严格、忽略约定空白或浮点误差容忍；默认不允许任意自定义判题脚本。
- 函数或模块测试明确参数序列化、异步支持、返回值及异常语义。
- 初始依赖和锁文件固定，评测时不临时联网安装。
- 完整课程包包含隐藏判题资料；学习端只获得题面、初始代码和公开样例。

## 7. 课程结构与学习体验

内容层级：**课程 → 章节 → 关卡 → 题目**。

每个关卡包含：学习目标、必要讲解、源码引用、练习、分级提示、通过条件和完成反馈。

学习页面采用题面与代码编辑区并列的布局，提供文件切换、语言配置说明、运行样例、提交评测、测试结果和历史提交。移动端优先阅读与查看进度，桌面端作为主要编码环境。

“运行”只验证公开样例，可允许受限自定义输入；“提交”使用固定题目版本运行公开与隐藏测试。样例通过不代表正式通过。每次提交保存代码快照、题目与评测版本，历史结果可追溯。

第一版学习规则：

- 学习者始终可以查看目录、关卡标题、目标和解锁条件。
- 第一关默认解锁；当前关卡所有必做题通过后解锁下一关。
- 必做编程题以全部必需测试通过（AC）为通关标准。测试点可展示得分作为反馈，但第一版不以部分得分替代 AC 解锁。
- 多选题使用完全匹配判分；排序题使用明确配置的有效顺序判分。
- 允许重复尝试，保存提交记录；已通过题目不会因后续答错而撤销通过状态。
- 分级提示与重试不扣分；完整参考实现默认 AC 后可查看。隐藏测试仅反馈类别和汇总结果，不返回测试源码、私有输入或期望输出。
- 已发布课程的判题与解锁在服务端执行，提交结果与进度更新保持一致。
- 刷新页面或换设备后能继续学习；重复提交不会生成重复的通关记录。

后续可以增加挑战跳级、章节分支、错题回顾和综合工程任务。

### 7.1 评测状态与反馈

| 状态 | 学习者看到的信息 | 是否通关 |
| --- | --- | --- |
| Queued / Running | 排队中 / 评测中 | 否 |
| AC | 全部必需测试通过 | 是 |
| WA | 输出不符或行为断言失败 | 否 |
| CE | 编译或类型检查失败，显示安全处理后的诊断 | 否 |
| RE | 运行异常，显示经过过滤的错误信息 | 否 |
| TLE / MLE / OLE | 时间 / 内存 / 输出超限 | 否 |
| System Error | 平台执行失败，可重试，不计作用户答错 | 否 |

公开样例可显示输入、期望值与实际结果；隐藏测试只显示允许公开的摘要。记录总耗时和资源信息，是否能可靠区分 MLE 等结果需要在执行服务验收时验证。

## 8. 课程包格式与导入导出

### 8.1 格式建议

采用 `.vlearn.zip` 作为完整课程包扩展名，内部使用 JSON、Markdown 和静态资源。格式本身独立于数据库和 AI 服务商。

建议目录：

```text
course.vlearn.zip
├── manifest.json          # 格式版本、课程身份、课程版本、来源与许可
├── course.json            # 章节、关卡、题目及依赖
├── content/               # Markdown 讲解
├── assets/                # 图片等资源
├── evidence/              # 源码引用与必要片段
├── problems/              # 各编程题的初始工程、公开样例及题目配置
├── grading/               # 隐藏测试、参考实现及客观题答案
├── runtimes.json          # 预置运行环境标识、版本及依赖摘要
└── checksums.json         # 文件完整性校验
```

完整包必须包含编程题的初始工程、公开样例、隐藏测试、参考实现与评测配置。导入动作只做解析和静态验证，绝不直接执行包内脚本；试评测和学习提交统一交给隔离执行服务。运行配置引用平台允许的预置环境，不接受包作者提供的任意镜像或宿主机命令。哈希校验只能检测完整性，不能证明作者身份或内容可信。

导入预览检查目标平台是否支持所需语言、运行配置与执行协议；缺失时保留草稿并明确标记不可发布，不允许静默替换运行环境。

### 8.2 版本与身份

| 字段 | 用途 |
| --- | --- |
| schemaVersion | 课程包格式版本，与内容版本分开 |
| courseId / courseVersion | 课程稳定身份与内容版本 |
| chapterId / levelId / questionId | 内容稳定身份 |
| questionRevision | 判断题目语义、答案或规则是否变化 |
| repository / commit | 固定课程对应的源码版本 |
| templateId / templateVersion | 记录题目的生成来源 |
| judgeVersion / runtimeProfile | 固定测试与运行环境，保障评测可追溯 |
| requiredPlugins / pluginLock | 课程必需插件、兼容范围和实际使用的精确版本及摘要 |

### 8.3 两种输出

- **完整可编辑课程包**：包含判分资料，供作者备份、编辑和迁移，导出需要作者权限。
- **学习内容输出**：供网页学习端加载，只提供当前授权范围的内容，不包含标准答案和隐藏测试。

第一版以完整包的导入导出为交付重点。浏览器学习接口按权限返回数据，不直接暴露完整包。学习内容输出不承诺离线自动判分，也不提供绝对防作弊保证。

### 8.4 导入规则

1. 检查文件大小、解压总大小、文件数量、路径越界及允许的资源类型。
2. 验证格式版本、结构、资源引用、ID 唯一性、题型和判分字段。
3. 验证关卡依赖不存在缺失引用或循环。
4. 检查完整性和来源信息；课程中的 Markdown 按受限规则渲染。
5. 展示导入预览，提示与现有课程的冲突。
6. 同 ID、同版本、相同内容重复导入视为已有；同 ID、同版本、不同内容拒绝静默覆盖。
7. 更新导入创建新草稿版本；复制为新课程时分配新的课程 ID。
8. 全部验证成功后完整保存，失败不留下可发布的半成品。

课程包不包含学习者的提交和进度。个人学习记录如需迁移，后续使用独立格式。

## 9. 课程发布与更新

课程状态：**草稿 → 校验通过 → 审核通过 → 已发布 → 已下架**。修改审核后的内容需要重新校验和审核。

已发布版本保持不可变，修改产生新版本。学习者默认继续当前已开始的版本，避免更新后进度或答案突然变化。

- 文案修正且题目语义、答案、判分规则未变化：允许在用户切换版本时复用进度。
- 学习目标、题目语义、答案、测试、运行配置或判分规则变化：提升相关修订版本，评估是否需要重新完成。不得静默重判或撤销历史 AC，必要的重判需单独标记并保留原结果。
- 源码 commit 变化：重新检查引用和受影响题目，不自动认定课程仍然有效。
- 下架版本不接受新用户开始；既有学习者的访问策略由管理员明确选择。

## 10. 系统组成与技术方案

以下为建议方案，实施时固定依赖版本并验证部署条件。

| 部分 | 建议方案 | 职责 |
| --- | --- | --- |
| Web 应用 | Next.js + TypeScript | 制作界面、学习页面、服务端接口 |
| 界面组件 | Tailwind CSS + shadcn/ui | 表单、路线、编辑和答题交互 |
| 登录与持久化 | Supabase Auth + PostgreSQL | 账号、课程版本、提交和进度 |
| 文件存储 | 对象存储，可使用 Supabase Storage | 课程包、资源与分析产物 |
| 格式协议 | JSON Schema + Markdown + ZIP | 导入、导出及跨平台校验 |
| 课程生成 | 独立后台任务 + AI 服务适配层 | 源码分析、分步生成和重试 |
| 编码界面 | 支持语法高亮与基础诊断的浏览器编辑器 | 在线敲代码、保存草稿、查看运行反馈 |
| 判题调度 | 独立任务队列 + 判题 Worker | 固定版本、排队、重试、汇总状态与解锁 |
| 代码运行 | 独立隔离执行服务 | 第一版公开样例与隐藏测试执行 |
| 客观题判分 | 服务端确定性规则 | 辅助题判分 |

网页请求只负责创建任务和查询进度，长时间分析在后台执行。生成任务记录阶段、状态、输入版本、产物、错误和消耗；失败可重试。模型和服务商配置留在服务端。

建议模块边界：项目导入、源码分析、模板管理、课程编排、课程包读写、代码工作区、评测调度、隔离执行、进度、账号与权限。生成队列与判题队列分开，避免长时间课程生成阻塞用户提交。

业务核心通过稳定 Interface 调用外部 Module，具体实现作为 Adapter 注入到可替换的 Seam。运行环境和数据库服务商不渗入课程协议；插件不得直接操作核心数据库或跳过权限、判题和发布校验。第一版采用模块化单仓库组织，Web、生成 Worker 和判题 Worker 独立运行，不要求每个模块都部署为微服务。

源码获取和分析产物按 commit 与分析配置复用；模板版本或学习目标变化时重新生成相关内容，避免误用缓存。

### 10.1 OJ 判题流程

1. 接口验证身份、关卡权限、代码大小和提交频率，保存不可变的代码快照。
2. 创建评测任务，绑定题目修订、评测版本和运行配置，返回提交 ID。
3. Worker 获取任务，在临时隔离环境中构建允许编辑的题目工程。
4. 编译或类型检查，按资源限制执行公开和隐藏测试。
5. 汇总结果，过滤敏感路径、测试细节与内部错误，保存测试摘要。
6. 服务端幂等写入最终结果，AC 后更新通关和解锁状态。
7. 学习端轮询获取进度；实时推送可后续增加。

第一版选定一个执行方案：采用支持所需协议的成熟评测服务，或在独立机器部署受限判题 Worker。上线前验证运行环境、隐藏测试隔离、资源限制和成本，不能只因为编辑器能运行样例就认为 OJ 已完成。

### 10.2 隔离与资源约束

- 用户代码和 AI 生成的测试均作为不可信程序处理，不在 Web 进程或包含业务凭据的机器环境中直接运行。
- 使用无特权临时沙箱，默认禁网，限制 CPU、内存、进程数、文件大小、输出长度与总执行时间；超限终止并清理。
- 不挂载宿主机敏感目录、容器管理接口和业务密钥，提交之间不共享可写工作区。
- 构建使用预置依赖，拒绝用户修改测试、评测器和运行配置。
- 隐藏测试与答案不放入用户进程可读目录；优先由独立评测器通过输入输出协议调用用户代码。函数题使用隔离执行适配层，不能把用户模块加载到持有全部隐藏测试的可信判题进程中。
- 单独验证死循环、进程滥用、网络请求、跨提交读取与测试探测的处置结果；队列具备并发限制与公平调度。

## 11. 数据对象与权限

本节定义概念对象，不作为最终数据库表结构。

| 对象 | 主要内容 |
| --- | --- |
| 用户 | 身份、角色 |
| 项目快照 | 仓库、commit、文件索引与源码材料 |
| 分析产物 | 模块、功能、证据与分析配置 |
| 题型模板 | 规则、结构、生成指令和版本 |
| 课程及版本 | 稳定身份、内容、来源、许可和发布状态 |
| 判分资料 | 隐藏测试、参考实现、比较规则、资源限制和评测版本 |
| 代码草稿 | 用户、题目修订、文件内容和保存时间 |
| 学习记录 | 用户、课程版本、通过状态和最近位置 |
| 答题提交 | 题目修订、代码快照、运行配置、评测版本、结果与时间 |
| 评测任务及结果 | 队列状态、执行次数、测试摘要、耗时与资源信息 |
| 生成任务 | 阶段、状态、产物、重试和消耗 |

权限原则：学习者仅可访问自己的记录及允许学习的内容；作者可管理自己的课程草稿与完整包；管理员可审核和下架。答案、AI 密钥和后台凭据不得通过普通学习接口返回。

多用户复用降低每次学习的 AI 成本，但访问、数据库、带宽与每次代码评测都有持续成本，需要监测。一次生成可以反复使用，不等于无限服务容量或零运行成本。

## 12. 实施阶段与验收

| 阶段 | 交付物 | 完成标准 |
| --- | --- | --- |
| P0：协议与样例 | 编程题规格、两种执行协议、插件契约、一份人工课程包 | 具备初始代码、测试和参考实现；插件身份、权限、依赖与版本规则明确 |
| P1：OJ 核心 | 编辑器、运行、提交、队列、隔离执行和结果 | 四类编程任务可评测；正确代码 AC；典型错误、超时和异常结果可区分 |
| P2：课程闭环 | 导入导出、登录、进度与线性解锁 | 编程题 AC 才解锁；多账号独立；导入后测试和代码模板仍可用 |
| P3：AI 制作与发布 | 项目分析、模板出题、试评测、版本管理与插件管理 | 生成约 6～8 关；错误变体被拦截；审核后发布；插件可导入、启停和兼容检查 |
| P4：工程题扩展 | 多文件功能题、重构、性能题与更多语言 | 按新增协议验收；不破坏已有课程和历史评测 |
| P5：内容生态 | 作者入驻、搜索、分享、评价和推荐 | 根据实际课程供给与用户需求决定是否启动 |

P0～P3 构成第一版目标。编程和隔离判题从第一版开始建设，先跑通人工编程课程的 OJ 闭环，再接入 AI 批量制作。

模块化贯穿 P0～P3，不等核心完成后再包一层插件。公开插件市场后置；首版以下载插件包、管理员导入、校验和启用的方式交付扩展能力。

## 13. 验证与观察指标

必须验证的关键场景：

- 课程包导入导出往返一致，损坏包、冲突版本和无效依赖被正确拒绝。
- 单选、多选、排序判分符合规则，答案未提前暴露。
- 同一行为契约的不同正确实现均可 AC；错误实现、空实现和只针对样例硬编码的实现无法通过针对性隐藏测试。
- 参考实现通过全部测试，预设错误变体被相应测试拦截，运行配置固定后结果稳定。
- 编译失败、运行错误、死循环、内存超限和输出超限有可理解的结果；平台故障不误报为用户错误。
- 用户不能读取隐藏测试、评测器或其他提交文件，不能修改受保护文件，也不能访问业务网络和凭据。
- Worker 失败或重复回传不造成重复通关；草稿保存与提交代码快照相互独立。
- 重复或并发提交不会造成进度错误；未解锁关卡不能绕过接口提交。
- 不同账号之间不能访问或修改彼此记录。
- 生成任务失败后可恢复，重新生成不覆盖人工修订。
- 课程版本更新不会静默改变学习者正在使用的内容。
- 用同一套契约测试验证可替换实现；安装示例模板插件不修改核心即可生成并使用新模板。
- 插件缺失、版本冲突、停用、回滚和重复安装均有明确结果，历史课程不会静默切换评测实现。

试用阶段记录：首次通关率、课程完成率、关卡退出位置、每题提交次数、AC 率、提示使用率、歧义反馈、生成成本、人工修改量、生成失败率、评测排队时间、评测耗时、系统错误率和单次评测成本。先建立基线，再设定数值目标。

## 14. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| AI 理解错误或编造答案 | 源码证据、分步生成、确定性校验与作者审核 |
| 题目能答对但没有教学价值 | 学习目标先行，评估是否能追踪和解释真实功能 |
| 项目体量导致成本失控 | 限定范围、设置预算、复用分析和分步重试 |
| 仓库更新使课程失效 | 固定 commit，独立发布课程版本 |
| 包中答案泄露到学习端 | 完整包限作者访问，学习接口过滤判分资料 |
| 导入包或源码包含不可信内容 | 限制解压与渲染，导入不执行，所有试评测与提交统一隔离 |
| AI 同时生成错误参考答案与错误测试 | 契约先行、独立检查、错误变体验证与作者审核 |
| 编程评测成本或排队失控 | 单语言起步、限额、资源预算、并发控制和独立队列 |
| 源码与素材分发权限不清 | 保存来源、许可证与署名，公开前审核使用范围 |

## 15. 开发前需要收敛的选择

这些选择不影响先定义课程协议和制作样例，进入对应阶段前确定即可：

- 第一门课使用哪个仓库、哪个 commit，以及面向什么基础的学习者。
- 第一版优先支持的语言与框架范围。
- AI 服务商、每次生成预算及允许发送的源码范围。
- 网站主要服务地区、部署位置和登录方式。
- 学习者可查看完整源码的时机、首批题目抽取范围和参考实现开放规则。
- 第一版运行语言、隔离执行方案、评测预算和资源限制。在线编辑与提交是已确定的核心能力。
