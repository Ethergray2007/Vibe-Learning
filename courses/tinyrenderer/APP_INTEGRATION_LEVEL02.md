## 1. 默认题面（供应用展示）

### 题目描述

完成 `line` 函数，把两个端点连成一条一个像素宽的线段。使用传入的颜色，包含两个端点，并保留线段之外的原有图片内容。

你可以编辑整份学习文件、添加辅助函数或改写实现。提交时需要保留下述函数接口；主程序用于运行观察。

### 输入约定

本题没有标准输入。提交检查器调用：

```cpp
void line(int ax, int ay, int bx, int by, TGAImage &image, TGAColor color);
```

`image` 是 16×16 的 RGB 图片；两个端点 `(ax,ay)`、`(bx,by)` 的坐标均为 0～15 的整数。左上角为 `(0,0)`，x 向右，y 向下。`color` 的顺序为蓝、绿、红、透明度（BGRA）；图片只比较前三个颜色通道。

### 输出要求

函数直接修改 `image`，不返回值。令 `n=max(|bx-ax|,|by-ay|)`；当 n>0 时，取 i=0～n，对下列位置四舍五入后画点：

```text
x = ax + (bx-ax) × i/n
y = ay + (by-ay) × i/n
```

这里的 i/n 是小数；坐标恰好落在半格时向较大的整数取整。n=0 时只画端点。除此以外的像素保持原样。

点击“运行”执行你的主程序，显示本次图片；点击“提交”检查函数在多种输入下的行为，全部通过才得到 AC。初始主程序以绿色绘制下方默认样例，生成 `preview.bmp` 和 `framebuffer.tga`。

### 公开样例

每例使用新的黑色图片，颜色为绿色 RGB(0,255,0)。表外像素均为黑色。

| 起点 → 终点 | 应画出的像素坐标 |
| --- | --- |
| (2,3) → (10,7)，默认预览 | (2,3),(3,4),(4,4),(5,5),(6,5),(7,6),(8,6),(9,7),(10,7) |
| (1,2) → (4,2) | (1,2),(2,2),(3,2),(4,2) |
| (3,1) → (3,4) | (3,1),(3,2),(3,3),(3,4) |
| (4,4) → (1,1) | (4,4),(3,3),(2,2),(1,1) |
| (2,1) → (3,4) | (2,1),(2,2),(3,3),(3,4) |
| (0,0) → (0,0) | (0,0) |
| (0,15) → (15,0) | (0,15),(1,14),…,(15,0) |

默认预览为黑底上 9 个绿色像素形成的阶梯线；应用使用最近邻放大。颜色和端点可在主程序中改动用于观察，不因观察图与默认样例不同就判 WA。

## 2. 实际代码契约与文件归属

签名来自现有 starter.cpp/reference.cpp，不新增参数、不改成标准输入输出题。`line` 是全局函数；提交测试需要可从检查器调用的定义。参数名可以变化，参数类型、顺序和可调用性保持。允许循环、辅助函数、整数或小数计算等不同实现，不比较源文件文本。

| 项目 | 实际行为约定 |
| --- | --- |
| 图片 | 调用者提供的 16×16、TGAImage::RGB，可能已有内容；不能清空、替换尺寸或改变非线段像素 |
| 坐标 | 四个整数均为 0～15；不要求越界裁剪。图片显示方向按逻辑坐标统一为左上原点 |
| 颜色 | 对目标像素写入调用者给定的 B、G、R 值，各为 0～255；不能写死绿色或交换通道 |
| alpha/bytespp | 沿用官方 TGAColor；RGB 图片不存储 alpha，判题不比较 alpha，也不新增对学习者的透明混合要求 |
| 端点 | 无论正向或反向均包含起终点；交换端点应得到相同像素集合 |
| 退化线段 | 两端相同，只改变该像素，不除零 |
| 其他 | 同一图上多次调用应累积绘制；后画的线在交点覆盖先画的颜色，其余背景保持 |

**实现自由与像素自由是两回事。** 本关现有契约规定了像素集合：长方向等步数采样，非负坐标的半格向上取整。只要输出符合契约，整数有理数、DDA、或采用等价取整规则的误差累积算法都可以通过。像素写入次序不比较，也不要求出现任何特定代码语句。

某些标准 Bresenham 写法在半格处选择另一侧像素。例如 (2,3)→(10,7) 的 x=3 处理想 y=3.5，本关要求 (3,4)，另一个算法可能选 (3,3)。那是另一种合理栅格化规则，不能据此宣称它在图形学上错误；但它不满足本题已公开的精确规则。**推荐本次保留现有规则并在题面明示，不要求必须使用 DDA 写法。** 若主对话决定接受多种栅格化结果，须另定连通性、像素覆盖、取整与反向一致性规则，同时修订题面、样例和检查器；不能只放宽为“有线就算对”，本次不作该变更。

| --- | --- |
| level-02/starter.cpp 的学习副本 | 整份文件可编辑；应用内部文件名可按已确认方案处理，不能截取 EDIT 片段保存 |

## 3. 运行与提交的判定边界

### 点击运行：只观察当前程序

保存并冻结当前完整学习文件，正常构建其 main 与固定 tgaimage.cpp，在本次独立工作目录执行。应用展示 main 实际产生的有效图片和错误；使用 runId 对应新产物，失败不展示旧图为本次结果。可改 main 观察其他端点、颜色、背景。

沿用现有图片解码/结构检查，默认工具应生成两个内容一致的 16×16 图片。缺图、损坏图或格式不支持给出输出错误；成功仅表示本次程序和图片可观察，judgment 为空，不更新 AC 或解锁。函数暂时不正确、甚至 main 只画了两个端点，也可运行成功。

### 点击提交：调用函数检查行为

不以学习者 main 生成的那一张图片判定第二关。检查器提供图片、端点和颜色，调用同一份提交代码中的 line，比较调用后图片的逻辑 RGB 像素。提交检查不依赖学习者是否调用 save_preview，不要求 main 保持样例绘制；提交图像不是本关 AC 的必要产物。编译接口必须有效。

建议复用 checks/line_check.cpp 的端点遍历、整数基准和逐像素比较，分为以下检查类别。公开样例可展示输入和差异；其他检查只反馈类别和汇总，作者日志不直接作为学习反馈。

| 类别 | 输入及判定 | 当前证据/补齐事项 |
| --- | --- | --- |
| 水平、垂直 | 覆盖两个方向、边缘 0/15，包含所有中间像素和端点 | 现有 65,536 种端点组合已覆盖 |
| 斜线、陡线 | 正负斜率，长方向分别为 x/y；含半格取整 | 现有穷举与整数基准已覆盖 |
| 反向端点 | 两种端点顺序与同一基准比较 | 现有穷举已间接检查一致性 |
| 单点 | n=0，只改变端点 | 现有穷举已覆盖 |
| 颜色 | 每个目标像素的 RGB 等于传入颜色 | 穷举仅用 BGRA{19,83,211,255}；绿/黄另有程序图片检查，不能称已穷举所有颜色 |
| 背景保持 | 目标点覆盖，其他点逐像素保持 | 现有穷举背景仅在 (15,15) 放 BGRA{7,11,13,255}，其他为黑色 |
| 连续调用 | 同一图片上两条异色线，检查交点覆盖及非线段内容 | 建议补齐，现有检查每例新建图片，未验证这一场景 |

补齐建议：增加少量红、蓝、白、黑及混合色调用；以不同位置的彩点/固定多色背景检查保持；增加连续绘制两条异色交叉线。黑色绘制须在有色背景检查，不能仅统计“非黑像素数量”。这些是应用接入验收需要补齐的案例，本次没有改检查程序，也没有宣称它们已验证。

现有独立基准计算方式（仅说明判分，不规定学习者实现）：n>0 时，令 k=0～n，

```text
x = (2×(ax×(n-k)+bx×k)+n) / (2×n)
y = (2×(ay×(n-k)+by×k)+n) / (2×n)
```

这里使用整数除法；因分子非负，结果等价于本题规定的四舍五入。检查器先生成目标坐标集合，再比较整图，不比较文件字节、摘要或图片压缩方式。现有检查没有像素误差容忍，也不接受多画一层抗锯齿像素。

全部必需行为检查完成并通过才 AC；失败为 WA。编译/链接失败为 CE，执行异常为 RE，超时为 TLE，宿主或进度持久化故障为 SE。检查器自己返回的“像素不符”退出码须映射 WA，不能统一把所有非零退出码映射 RE；正常提前退出但未完成全部检查也不能 AC。具体报告载体与现有 API 的适配由主对话确认。

## 4. 最小防样例硬编码方式与完整文件编辑方案

**最小方式：宿主控制输入，函数判题，逐像素比较。** 固定画默认图的 main 不参加行为检查；line 为空或只画默认图时，其他端点输入就失败。无需源码字符串匹配或要求循环长什么样。有限行为测试不承诺阻止熟悉全部测试的恶意绕过，本地自学仍须结合迁移解释。

现有作者检查通过 candidate.inc 把学习代码包含进检查器，并定义 COURSE_TEST。starter.cpp/reference.cpp 已用 `#ifndef COURSE_TEST` 包住 main，因此原样可测试。但整文件编辑后，学习者可能重写普通 main、删除条件宏；直接包含就会出现两个 main。把“删宏”当作算法错误，会与完整编辑要求冲突。

**推荐待确认方案：分别编译学习文件与宿主检查器，提交构建重命名学习者入口。**

1. 运行构建保持学习者完整源文件，不改名 main。
2. 提交仅在宿主构建参数中对学习者翻译单元定义 `COURSE_TEST`，并把 `main` 宏重命名为宿主保留名称（例如 `vibe_learning_observe_main`）。原有条件宏可保留；删掉条件宏的普通 main 会被改名，不与检查器入口冲突。不回写学习者源文件，不依赖字符串裁剪。
3. 检查器作为独立翻译单元编译，自行包含 tgaimage.h、algorithm 等所需头，并按现有签名声明 line。复用 line_check.cpp 的检查逻辑，替换 candidate.inc 的直接包含方式；与学习者目标文件及固定 tgaimage.cpp 链接。
4. line 与自定义辅助函数应放在 main 外、不要连同 line 一起放进 `#ifndef COURSE_TEST`；对外提供全局、可链接的 line。缺失定义或把它改成不可链接的 static/命名空间函数，应给出接口诊断。其内部辅助函数可自由组织。
5. 宿主以检查器完成全部必需检查的结果汇总判定，不能根据学习者输出的“PASS”字样或仅凭进程返回 0 写入 AC。静态初始化异常、提前 exit、死循环等交由宿主报告和终止。

取舍：保留单文件完整编辑、普通 main 和函数测试；不用约束固定前后缀。代价是提交多一个受控构建步骤，仍需保留可链接的 line 接口，并验证入口重命名对学习代码的兼容性。该方案不是完整沙箱，不能据此承诺不可信 C++ 无法访问宿主文件。

备选为要求保留 COURSE_TEST 包裹 main，直接复用当前包含式检查器；实现简单，但对完整编辑存在额外结构约束，且学习者宏可能影响同一翻译单元中的检查器。推荐分别编译方案；**本次只交提案，不实现入口转换、检查器改造或新接口。**

## 5. 知识、提示、反馈与迁移（独立区域）

知识区复用 lesson.md“只学本题需要的 C++”：整数/小数、引用参数、条件返回、循环、绝对值与最大值、取整。不要把整段讲解混入默认题面；题面保留决定输出的取整规则。

### 典型错误反馈

| 检查现象 | 给学习者的简短反馈 |
| --- | --- |
| 只有两端、中间缺点 | 线段中间还有空格。请检查是否画出了每一步的位置。 |
| 漏终点 | 终点没有画出。请检查循环是否包含最后一步。 |
| 大多数点停在起点 | 中间进度可能变成了 0。请检查除法是否保留小数。 |
| 竖线或反向线失败 | 这条线不一定向右走。请同时考虑横向和纵向的变化。 |
| 陡线缺点 | 纵向距离更长时，也需要足够多的步数。 |
| 单点失败 | 起点和终点相同时，只需画一个点；此时步数是 0。 |
| 半格像素偏一格 | 本题在恰好半格时向较大的坐标取整。请核对取整规则。 |
| 颜色不符 | 请使用传入的颜色，并确认本版本按蓝、绿、红顺序存储。 |
| 背景被擦除 | 画线只应改变线上的像素，保留图片原有的其他内容。 |
| 找不到 line / 签名不符 | 提交检查需要调用题面中的 line 函数，请恢复可调用的接口。 |

以上是定位建议，不从单个现象断言源码一定存在某种错误。隐藏案例只返回类别；公开案例可显示端点、期望与实际坐标。

### 逐级提示

1. 横向和纵向分别要走多少格？选择较长方向决定步数，才能避免漏格。
2. 两端相同时单独画点；其他情况让进度从 0 走到 1，包含两端。
3. 用 `double(i)/steps` 计算进度，分别计算 x、y 并取整，再写入传入的颜色。

答案解析独立展示 reference.cpp 与 lesson.md“答案解析”，默认 AC 后可查看；用户主动提前查看时记录已看答案。其核心是步数、端点包含、单点处理和颜色传递，不要求照搬代码。查看答案不改变行为判题，但不作为独立完成证据。

### 迁移练习：倒着画一条陡线

沿用既有迁移题：保留自己的 line，修改主程序，在黑底画 `(5,12)`→`(2,3)` 的黄色线 RGB(255,255,0)。先预测 dx、dy、steps 及第 0、3、6、9 步的位置，再运行；交换端点重画，比较结果。

可自动检查：两幅逻辑 RGB 图片相同，恰有规定的 10 个黄色像素，其余黑色；调用自己的函数在不同输入下仍满足行为契约。主任务函数 AC 与迁移图片通过分别记录，不把迁移图片通过直接当作理解验证。

需真人判断：能否先独立预测、解释为何步数是 9 而非 3、为何包括第 9 步、为何交换端点不改变图形；结合是否查看答案、提示或依赖 AI 生成整题代码，不仅看最后结果。

迁移答案延后展示，沿用 transfer.cpp 与 lesson.md：dx=-3、dy=-9、steps=9；指定四步为 (5,12)、(4,9)、(3,6)、(2,3)。全部点为 (5,12),(5,11),(4,10),(4,9),(4,8),(3,7),(3,6),(3,5),(2,4),(2,3)。BGRA 黄色为 {0,255,255,255}。现有 transfer.cpp 包含参考实现，是答案资料，不应误作学习者初始代码。
